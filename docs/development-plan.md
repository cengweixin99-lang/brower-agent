# 浏览器 Agent 开发计划

日期：2026-11-13。依据：[技术架构](technical-architecture.md)。先交付真实 Demo，再进入内测和生产；阶段以验收结果结束。

当前已完成 P01–P05：通用协议、状态规则、受控评测设施、运行持久化、持续浏览器会话、页面观察与截图存储，以及真实原生交互、动作去重与停止撤销。新会话通过内部网关使用，页面脚本与网络写入仍禁用；模型决策和前端贯通待后续阶段。旧采集链路继续保留，基础设施测试不等于 Agent 能力验收。

**排期假设**

按一名熟悉仓库的全栈开发者持续投入估算，单位为有效开发人日，包含相应实现、测试和文档；不是日历交付承诺，也不是 AI 执行耗时预测。人手、首批网站和模型表现尚未确定，先给区间；完成 D0 和首次模型评测后重新估算。外部账号、基础设施开通及等待反馈时间另计，日历排期建议再留约 20% 联调与修复余量。

**每项任务的完成规则**

- 一个任务完成时，交付可运行增量、验收结果、变更说明和已知限制；更新本表状态并补充证据链接。
- 代码变更遵循仓库规则：Node 24、pnpm 11.25.0、固定直接依赖版本，安装使用 `--ignore-scripts`；执行 `pnpm check` 和直接相关测试，涉及 Web 时验证构建。
- 检查存在既有失败时记录基线及差异，不能声称全绿；新增失败修复后才能验收。停止、权限、重复执行等阻断问题优先于新能力。
- 任务扩展若改变架构、阶段范围或费用，应先更新相应设计与计划；不在开发中顺手加入多 Agent、技能市场或额外基础设施。
- 本计划的状态更新由实际开发结果驱动，不创建定时自动化，不自动提交 Git。
