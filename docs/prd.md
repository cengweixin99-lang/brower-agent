版本：0.3 草案

## 1 产品定位与目标

Browse Agent 是一个通过自然语言驱动浏览器任务的工作台。用户描述目标并选择浏览器会话，Agent 执行网页研究、信息比较和数据提取；用户可以查看执行过程、暂停或补充指令，并在对外发布结果前作出决定。任务结束后，用户可以从历史记录查看过程和下载产物。

首个完整场景沿用原型：比较 Linear、Asana、Notion 的定价和 AI 功能，为 20 人团队生成比较表与建议。该场景用于验收工作流，产品不能把三个网站、模型名称、价格或六个执行步骤固定为业务逻辑。

产品目标是让用户能启动任务、理解进展、及时干预，并找回可追溯的结果。目标用户暂定为需要跨网站研究和整理信息的产品、运营、研究人员；这是基于原型场景的定位，尚无用户访谈结论。

## 3 首版范围

P0 为首版核心闭环；P1 为后续增强。原型中出现入口，不等于首版必须具备对应完整业务能力。

| 范围                                   | 优先级     | 首版交付定义                                              |
| -------------------------------------- | ---------- | --------------------------------------------------------- |
| 新任务与模板                           | P0         | 描述目标、选择可用会话和模型、填入模板、提交任务          |
| 执行工作区                             | P0         | 活动记录、浏览器预览、暂停、恢复、停止、补充指令          |
| 审批与结果                             | P0         | 审阅待执行动作、选择发布或仅保留产物、展示结果与失败信息  |
| 任务历史                               | P0         | 搜索、筛选、分页、详情、返回执行记录、下载产物            |
| 浏览器会话                             | P0         | 查看已配置会话、连接状态、启动与停止；会话创建流程列入 P1 |
| 跨页状态一致性                         | P0         | 进入历史或会话页不打断任务，返回时展示最新状态            |
| Screenshot 与 DOM Inspector            | P1         | 可追溯到明确时间和页面的只读快照；首版未接入时明确不可用  |
| 附件、表单提交、会话新建及编辑         | P1         | 文件类型、大小、授权和具体执行范围另行定义                |
| 定时任务、团队协作、计费与高级账户设置 | 不纳入首版 | 原型只有部分导航线索，没有足够业务定义                    |

首版研究结果在工作台保存和导出，对外发布沿用原型的 Notion 私有页面场景。完成真实账号授权、目标位置确认、审批和执行结果核对后，才可开放真实发布。未接入时不得把模拟成功显示为真实发布成功。

## 4 信息架构与导航

| 区域或入口                       | 行为                       | 依据与补充                                                           |
| -------------------------------- | -------------------------- | -------------------------------------------------------------------- |
| New Task                         | 打开空任务编辑页           | 已核实；未提交草稿在当前会话内切页保留为补充规则                     |
| All Tasks、Recent Tasks、History | 进入任务历史               | 已核实三者均连到历史画板；首版共用列表，Recent 默认近 7 天为补充规则 |
| Browser Sessions                 | 进入会话管理页             | 已核实导航目标                                                       |
| 固定任务卡片或返回当前任务       | 打开相应任务工作区         | 已核实入口；任务 ID 必须保持不变                                     |
| Scheduled Tasks                  | 展示暂未开放说明           | 入口已核实，定时能力不在首版范围                                     |
| Settings、Help、账户与工作区选择 | 设置、帮助和账户上下文入口 | 入口已核实；首版不据此推断多租户、成员管理或工作区切换能力           |

补充规则：切换页面只改变视图，不暂停或重建任务；浏览器刷新后按任务 ID 恢复服务端状态。离开编辑页前保留草稿，任务提交成功后清空对应草稿，失败时保留。关键操作成功或失败均提供可理解的反馈。

## 5 核心用户流程

### 5.1 创建并完成研究任务

1. 用户进入 New Task，输入目标或点击模板填入可编辑文本。
2. 用户选择可用浏览器会话及模型，点击 Run Task 或使用 Command Enter 提交。
3. 系统确认创建成功后进入该任务工作区，显示任务 ID、状态和执行活动。
4. Agent 根据实际执行事件更新思考、搜索、浏览、提取、整理等阶段；用户可查看浏览器页签和来源。
5. 若只需生成结果，任务可直接完成；若下一步需要对外发布或提交，进入待审批状态并展示具体动作。
6. 用户选择批准执行或仅保留结果。系统确认产物或外部动作的真实结果后更新状态。
7. 用户查看报告或下载文件，也可从历史记录再次打开。

已实际核实的演示分支为：向 Notion 创建私有页面前审批，Reject 后报告留在当前工作台，Approve 后经 Submitting 进入模拟发布完成；本地保留页的 Save to Notion 可以再次进入审批。其他动作何时需要审批、普通研究何时直接完成仍属于补充规则。修复后的空任务 Run Task 显示校验错误；有内容的草稿经 Creating 进入执行，创建失败保留示例草稿并提供重试。原型内自动推进的延时只用于演示，不能用于正式状态流转。

### 5.2 执行中干预

用户点击 Pause 后，界面先显示暂停处理中；后端确认到达安全停止点后显示 Paused。恢复从当前任务的已有进度继续。Stop 结束后续调度并保留已经产生的记录，不承诺撤回已发生的外部动作。补充指令属于同一任务的输入，需要显示是否已接收、何时生效；新增对外动作仍须重新审批。

### 5.3 跨页面查看

任务执行中进入 History 或 Browser Sessions 后，任务仍继续推进。用户通过固定任务卡片或历史记录返回原任务，看到一致的任务阶段、暂停状态和结果。历史页的详情选择与“打开执行页”是不同操作，查看详情不能创建新的执行实例。

## 6 页面功能需求

### 6.1 新任务

来源：新任务空状态与已填任务画板。下表中的校验、失败处理与提交约束为补充规则。

| 编号   | 需求             | 交互与验收要点                                                                                                                                             |
| ------ | ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NEW-01 | 编辑自然语言任务 | 支持多行；去除首尾空白后为空则不可提交；普通 Enter 换行                                                                                                    |
| NEW-02 | 五个模板入口     | 已启用的模板只填入草稿，不立即执行；当前原型 Research competitors 与 Compare products 可启动，Extract website data、Fill out web forms、Summarize articles 为明确标注的独立预览；后续启用需补相应执行验收 |
| NEW-03 | 选择会话         | 展示名称与可用状态；不可用时给出前往会话页的操作；不能静默改用其他会话                                                                                     |
| NEW-04 | 选择模型         | 显示后端允许使用的模型；未配置或无权限的项不可选；原型的 Claude Sonnet 4.5 仅是示例                                                                        |
| NEW-05 | 提交与防重复     | 点击或快捷键等价；提交期间显示处理中并防重复；成功返回任务 ID，失败保留草稿并可重试                                                                        |
| NEW-06 | 最近任务         | 展示名称、摘要、状态、时间；点击已有任务只打开记录；View all tasks 进入列表                                                                                |

附件入口在未实现真实文件能力时应隐藏或明确不可用，不能以“已附加”提示暗示内容已供 Agent 使用。草稿长度、文件大小与支持类型在附件功能排期时确定。

### 6.2 执行工作区

来源：执行工作区画板及暂停、停止、标签切换连线。事件、命令和异常规则为补充规则。

| 编号    | 需求       | 交互与验收要点                                                                             |
| ------- | ---------- | ------------------------------------------------------------------------------------------ |
| EXEC-01 | 任务概况   | 展示任务 ID、目标摘要、状态、可用操作；所有信息归属同一任务                                |
| EXEC-02 | 活动时间线 | 按事件顺序展示时间、阶段、动作、结果与错误；可展开工具调用摘要，不显示凭证或敏感参数       |
| EXEC-03 | 执行进度   | 反映真实完成步骤；计划变化时允许调整总步数；未知进度显示处理中，不伪造百分比               |
| EXEC-04 | 浏览器预览 | 展示所选会话、活动页签、URL 和连接状态；标签切换只改变查看对象，不重启任务或触发另一段执行 |
| EXEC-05 | 暂停与恢复 | 每个可执行阶段均能请求暂停；确认暂停后不调度新动作；恢复沿用任务 ID 和已完成步骤           |
| EXEC-06 | 停止       | 请求后锁定重复操作，确认完成后显示 Stopped；结束态不能直接 Resume，重新执行创建新任务      |
| EXEC-07 | 追加指令   | 接收后写入活动记录并反馈生效状态；Running 和 Paused 可提交；结束态不可提交                 |
| EXEC-08 | 数据更新   | 跨页面、重连和刷新后读取最新状态；重复事件不重复展示，旧事件不覆盖较新结果                 |

耗时定义为实际执行耗时，不包含暂停和等待用户审批的时间；另保存创建时间和结束时间。浏览器预览默认只读，首版不提供直接接管网页操作。截图和 DOM 视图未就绪时不能复用实时预览并声称是历史快照。

### 6.3 审批与结果

来源：已实际操作审批画板 `8:3072`、发布完成 `8:3312`、本地保留 `8:3552`。审批页明确显示目标为 notion.so 的 Personal workspace，动作为 Create a private page，按钮为 Reject / Approve；Reject 完成后保留报告，并可通过 Save to Notion 重新申请发布。下表中的真实执行、版本绑定、错误处理和导出规则为补充定义。

| 编号   | 需求               | 交互与验收要点                                                                                                            |
| ------ | ------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| APR-01 | 展示待审批动作     | 用户可看到动作类型、目标服务与位置、拟提交内容、会影响哪些数据，以及关联研究结果                                          |
| APR-02 | 审批绑定具体内容   | 批准只适用于当前任务的指定动作及内容版本；目标或内容变化后原批准失效                                                      |
| APR-03 | 批准执行           | 点击后显示处理中；真实执行确认成功后才能显示 Published；重复点击或请求重试不能重复发布                                    |
| APR-04 | 拒绝发布并保留结果 | Reject 后报告留在当前工作台且任务完成，不发生对外发布；本地完成页提供 Save to Notion 再次审批，存储位置与保留期限仍待决策 |
| APR-05 | 发布失败或结果未知 | 保留研究产物，显示原因及恢复操作；结果未知时先核对外部状态，不能直接重复提交                                              |
| RES-01 | 查看与导出结果     | 展示内容、来源 URL、生成时间和发布状态；原型已有完整预览、Open in Notion、复制链接和导出反馈；生产版本须打开真实结果、复制真实链接并下载可校验文件 |

任务完成与发布状态分别记录。例如研究产物已生成但发布失败时，不能把研究结果一并丢弃，也不能显示“已发布”。Notion 已由审批页确认是该演示场景的发布服务；真实账号、父级页面、授权方式及存储实现仍需定义。

核对结果区分确认已发布、确认未创建、核对失败和仍待确认。只有确认未创建才开放重新发布；其他不确定结果只允许只读核对。Submitting 的 Check status 不创建第二次发布请求；Checking 的 Cancel check 保留结果待核对。Figma 的延时会受浮层打断影响，已补手动继续入口；生产任务和发布动作必须在切页后继续由服务端推进。

### 6.4 任务历史

来源：历史画板。搜索占位文本明确为按任务名称或网站搜索；筛选、分页和下载的具体处理规则为补充规则。

| 编号   | 需求         | 交互与验收要点                                                                                                                                                   |
| ------ | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HIS-01 | 任务列表     | 展示任务名称、网站或结果摘要、创建时间、耗时、状态；默认按创建时间倒序                                                                                           |
| HIS-02 | 状态筛选     | 保留 All、Running、Completed、Failed；实测暂停任务在 All 中显示 Paused，Running 计数为 0。建议增设暂停、待审批和停止筛选；最终分类待确认，不将其静默归入 Running |
| HIS-03 | 搜索与日期   | 任务名称或来源网站可匹配；搜索、日期与状态条件取交集；默认近 30 天；日期按工作区配置的时区计算并明确展示该时区；Clear search 仅清除查询，保留其他条件 |
| HIS-04 | 分页         | 初始每页 8 条，与原型一致；条件改变回第一页；记录不足时更新页数并禁用越界翻页                                                                                    |
| HIS-05 | 执行详情     | 选中任务后展示 ID、状态、时间、用时、会话、模型、输出及下载；筛选后选中项不可见时关闭详情                                                                        |
| HIS-06 | 返回执行记录 | View full execution 打开同一任务；进行中展示最新进度，已结束展示留存过程与产物，不隐式重新运行                                                                   |
| HIS-07 | 列表状态     | 区分首次无任务、筛选无结果、加载中和加载失败；分别给出新建、清除条件或重试操作                                                                                   |

筛选计数按当前搜索与日期条件计算各状态数量；当前状态选项不反向限制其他选项计数。设计中的 24 条任务、42 家公司、12.8 KB 均为示例，不固定到业务数据。

新增静态筛选演示分别包含 20 条已完成记录、研究完成后包含当前任务的 21 条记录，以及 3 条失败记录；已完成筛选有三页，返回保留底层任务。其页面采用 6/8 条混合排布，部分示例记录也未按日期排序；正式实现仍遵守 HIS-01 的创建时间倒序和 HIS-04 的统一分页规则，不照搬静态样本的排列。

### 6.5 浏览器会话

来源：会话页入口、Research sandbox 组件及会话状态页 `8:7989` 的浏览器实测。已核实个人会话的页签与占用任务展示、View browser 返回暂停任务、沙盒启停，以及沙盒连接状态在本次跨页往返中保持。整页右上为 New Task；没有据此确认新建会话能力。其他运行规则为补充定义。

| 编号   | 需求       | 交互与验收要点                                                                           |
| ------ | ---------- | ---------------------------------------------------------------------------------------- |
| SES-01 | 查看会话   | 展示名称、连接状态、打开页签数与最近使用信息；会话列表与任务列表分开管理                 |
| SES-02 | 启动与停止 | Research sandbox 的 Resume session 与 Stop session 发出会话命令；处理期间防重复，结果以网关确认为准；Personal session 暂不提供手动断开 |
| SES-03 | 绑定任务   | 任务创建时记录会话 ID；之后切换编辑器选择不改变已有任务的会话                            |
| SES-04 | 会话占用   | 首版同一会话同一时刻只允许一个任务持有执行权；冲突时提示正在使用的任务，禁止抢占         |
| SES-05 | 停止影响   | Running 与 Paused 都持有会话执行权；先停止持有任务才释放占用，不能仅暂停后抢占或断开。Personal session 释放任务占用后仍保持浏览器连接；沙盒启动后不自动恢复旧任务 |
| SES-06 | 会话隔离   | 不同会话的登录态和 Cookie 不混用；停止会话不等于删除保存的配置；故障不显示成用户主动停止 |

会话的新建、重命名、删除和登录接管属于后续范围；现有本地原型里的新建弹窗仅用于演示。真实登录、验证码等需要用户处理时，任务应进入可解释的等待或暂停状态并提供返回路径。

## 7 状态与控制规则

状态机为补充定义，用于把原型画板转换为可实现的业务规则。任务状态、执行阶段、浏览器连接状态和结果发布状态分别建模；51 张画板不能直接对应 51 个独立业务状态。

| 任务状态       | 进入条件                         | 可用操作                                       | 允许的后续状态                                     |
| -------------- | -------------------------------- | ---------------------------------------------- | -------------------------------------------------- |
| Running        | 创建成功或恢复成功               | 暂停、停止、补充指令                           | Paused、Needs approval、Completed、Stopped、Failed |
| Paused         | 后端确认暂停，或依赖的会话不可用 | 恢复、停止、补充指令                           | Running、Stopped、Failed                           |
| Needs approval | 即将执行需要用户决定的动作       | 批准、仅保留结果、停止                         | Running、Completed、Stopped、Failed                |
| Completed      | 任务目标已完成，产物已保存       | 查看、下载、新建；本地保留报告可另发起发布审批 | 研究任务保持结束态，发布状态独立变化               |
| Stopped        | 用户停止已获确认                 | 查看已留存过程、重新创建任务                   | 保持结束态                                         |
| Failed         | 执行失败且无法自动恢复           | 查看错误、下载已有产物、重新创建任务           | 保持结束态                                         |

创建中、暂停处理中、恢复处理中、停止处理中和批准处理中是操作反馈，不冒充已确认的业务结果。执行阶段可包含 Thinking、Searching、Browsing、Tool call、Summarizing；阶段可重复或跳转，不要求按示例固定执行。

结果发布状态独立取值：无需发布、未决定、待审批、仅保留、发布中、已发布、发布失败、结果待核对。普通研究任务可以无需审批直接完成；只有发生需确认的对外动作时才进入 Needs approval。原型允许已完成且本地保留的报告再次 Save to Notion：建议为已有产物创建独立发布审批，研究任务保持 Completed，界面突出发布待审批；不要重跑研究，也不要让研究耗时或进度回退。

## 8 异常与恢复要求

以下均为补充规则，需纳入前后端联调验收。

| 场景                     | 用户看到的反馈                   | 系统与恢复行为                                   |
| ------------------------ | -------------------------------- | ------------------------------------------------ |
| 创建请求超时             | 创建结果待确认，保留草稿         | 查询同一次请求的结果，避免重复创建任务           |
| 会话断开或启动失败       | 当前连接问题及恢复入口           | 暂停依赖该会话的后续动作，不擅自切换会话         |
| 网站加载失败或需要登录   | 对应步骤失败或等待用户处理       | 有限重试；仍不可用时保留其他成果并说明缺失来源   |
| 模型不可用或凭证未配置   | 可理解的错误和选择其他模型的入口 | 不静默切换计费模型，不把错误当成完成             |
| 刷新、切页、事件连接中断 | 状态更新提示                     | 依据任务 ID 拉取快照并续接事件，不能重新开始执行 |
| 暂停与完成同时发生       | 展示后端最终状态                 | 已结束任务不被较晚到达的暂停响应回退             |
| 发布结果未知             | 显示正在核对，保留报告           | 使用动作记录确认是否已经生效，禁止盲目重放       |
| 下载失败或产物过期       | 下载不可用的原因与重试入口       | 不返回空文件冒充结果                             |

## 10 数据与系统约束

本节定义前后端需要一致理解的数据，不预设尚未实现的 API 路径。

| 对象       | 最小信息                                                                              |
| ---------- | ------------------------------------------------------------------------------------- |
| 任务       | ID、目标、名称、会话 ID、模型标识、状态、阶段、创建与结束时间、有效执行耗时、错误摘要 |
| 执行事件   | 事件 ID、任务 ID、顺序号、时间、类型、展示摘要、必要的来源或产物引用                  |
| 补充指令   | 指令 ID、任务 ID、内容、接收时间、接收及生效状态                                      |
| 审批动作   | 审批 ID、任务 ID、动作类型、目标、内容版本、决定、决定时间、执行结果                  |
| 产物       | 产物 ID、任务 ID、类型、名称、大小、生成时间、来源、保存及发布状态                    |
| 浏览器会话 | ID、名称、连接状态、最近使用时间、页签摘要、当前占用任务                              |

任务创建、暂停、停止和审批应能够处理重复请求；状态事件应可排序和去重。正式版本的任务记录与产物必须能在刷新后恢复，保留期限和存储位置见待决策项。

系统边界沿用 [现有架构](architecture.md)：web → api → Temporal workflow → activity → agent → browser-worker gateway → 浏览器。浏览器动作通过网关执行；agent 包不直接引入 Playwright。Temporal workflow 只负责确定性编排，I/O 在 activities 执行。具备外部副作用的动作重试前必须核对执行记录。

凭证、Cookie、包含秘密的任务内容、会话配置和截图不得写入 Git；用户可见活动和错误信息需移除秘密。网页内容作为任务输入，不能自行成为授权发布或提交的依据。

目前后端主要具备环境检查与健康接口，真实浏览器任务编排和认证网关动作仍待开发；现有前端为内存演示，刷新即重置，不能视为上述持久化和执行能力已交付。
